<p><strong>适用场景</strong>：Arch Linux 与 Windows 11 位于同一块物理 NVMe SSD；希望在物理启动 Windows 和 Arch 内的 KVM Windows 之间复用<strong>同一个 NTFS 系统分区</strong>，同时将 NVIDIA 显卡直通给虚拟机。本文只覆盖<strong>物理分区映射、虚拟 EFI、Windows 引导、VirtIO SCSI、VFIO、<code>winvm</code> / <code>mdadm linear</code> 管理</strong>；不讨论 HugePages、CPU Pinning、Looking Glass 的配置。</p>
<p><strong>风险提示</strong>：这是高风险的共享系统盘方案。操作前备份 Windows 的重要数据、BitLocker 恢复密钥及虚拟 EFI 文件。<strong>同一时间只能有一套 Windows 使用这个 NTFS 分区</strong>。不要把运行 Arch 的整块 NVMe 设备直通给虚拟机。本文中的设备路径和扇区数来自这台机器的实际布局，移植到别的电脑时必须重新核对，不能照抄。</p>
</blockquote>

<h2 id="heading-8" data-id="heading-8">3. 建立 KVM 虚拟机与独立 Windows EFI 引导</h2>
<h3 id="heading-9" data-id="heading-9">3.1 虚拟机基础设置</h3>
<p>在 Virt-manager 创建 Windows 11 虚拟机，使用：</p>
<ul>
<li>连接：<code>qemu:///system</code>，芯片组：Q35，固件：OVMF UEFI。</li>
<li>CPU：<code>host-passthrough</code>；内存、核数按需要分配。</li>
<li>先用 <strong>QXL/SPICE 虚拟显卡</strong>完成安装和诊断，后续 VFIO 验证后再禁用虚拟显卡。</li>
<li>将已有磁盘 <strong><code>/dev/md/winvm</code> 作为整个块设备</strong>添加，初始使用 <strong>SATA</strong> 总线（Windows 自带 AHCI 启动驱动）；不是将 <code>/dev/md127p2</code> 单独作为启动盘。</li>
<li>临时挂载 Windows 安装 ISO，用于 WinPE 重建<strong>虚拟 EFI</strong> 中的 Windows Boot Manager。</li>
</ul>

<h2 id="heading-11" data-id="heading-11">4. SATA → VirtIO SCSI（先装驱动，再换系统盘）</h2>
<p>初次采用 SATA 是为确保原 Windows 直接启动；稳定后再改为 VirtIO SCSI，减少 AHCI 设备模拟开销。<strong>一定先安装 <code>vioscsi</code> 驱动，不能直接把引导盘总线改成 SCSI。</strong></p>

<h2 id="heading-15" data-id="heading-15">5. <code>winvm</code>：恢复和停止 MD Linear 的管理脚本</h2>
<p><code>mdadm --build</code> 建立的是<strong>没有持久 MD 超级块</strong>的线性阵列。重启 Arch 后，<code>/dev/md/winvm</code> 会消失，两个 Loop 设备也可能改变编号；<strong>不能指望普通 RAID 自动扫描永久恢复</strong>。因此使用脚本按固定顺序重建：</p>
<ul>
<li><code>sudo winvm start</code>：检测并恢复映射，验证关键几何结构。</li>
<li><code>sudo winvm stop</code>：只在 VM 已关机、相关文件系统没有挂载时停止映射并释放 Loop。</li>
<li><code>sudo winvm status</code>：输出 MD、Loop、实体 NTFS 和 VM 状态。</li>
<li><code>sudo winvm restart</code>：安全停止后再次恢复。</li>
</ul>
<h3 id="heading-16" data-id="heading-16">5.1 建立脚本</h3>

<h3 id="heading-17" data-id="heading-17">5.2 常见故障与对应解释</h3>
<p><strong>A. 重启后虚拟机报</strong> <code>Cannot access storage file &#39;/dev/md/winvm&#39;: No such file or directory</code>：MD Linear 没有持久超级块，先运行 <code>sudo winvm start</code>；启动 VM 之前核对 <code>sudo winvm status</code>。</p>
<p><strong>B. <code>cat /proc/mdstat</code> 提示不存在</strong>：不必单凭该文件判断 MD 是否可用，以 <code>mdadm --detail /dev/md/winvm</code>、<code>lsblk</code> 和 <code>blockdev --getsz</code> 为准。</p>
<p><strong>C. 脚本提示 EFI 分区起点异常，但 <code>lsblk -o START</code> 看到 2048</strong>：旧脚本使用 <code>lsblk -ndo START</code> 可能因为 <code>-d</code> 的设备过滤而得到异常输出；新版使用 <code>lsblk -nr -o START</code>。不能因此重新执行 <code>sgdisk --clear</code>。</p>
<p><strong>D. <code>target &#39;sda&#39; duplicated for disks</code></strong>：临时测试盘与系统盘使用了同一 target 名称；修改测试盘名称或移除它，不需要改变物理 Windows 分区。</p>
<p><strong>E. 物理 Windows 与 KVM 时间差</strong>：实体 Windows 若设置了 <code>RealTimeIsUniversal=1</code>，虚拟机的 RTC 建议 <code>&lt;clock offset=&quot;utc&quot;&gt;</code>，不要使用 <code>localtime</code>。</p>
<h2 id="heading-18" data-id="heading-18">6. 日常启停与切换实体 Windows</h2>
<h3 id="heading-19" data-id="heading-19">Arch → KVM Windows</h3>
<pre><code class="hljs language-bash"><code class="hljs language-bash" data-raw="sudo%20winvm%20start%0Asudo%20winvm%20status%0Asudo%20virsh%20-c%20qemu%3A%2F%2F%2Fsystem%20start%20win11"><div class="code-row">
            <span class="line-num" data-num="1"></span>
            <span class="code-content"><span class="hljs-built_in">sudo</span> winvm start</span>
          </div><div class="code-row">
            <span class="line-num" data-num="2"></span>
            <span class="code-content"><span class="hljs-built_in">sudo</span> winvm status</span>
          </div><div class="code-row">
            <span class="line-num" data-num="3"></span>
            <span class="code-content"><span class="hljs-built_in">sudo</span> virsh -c qemu:///system start win11</span>
          </div></code>
</code></pre><p>启动前确保 Windows NTFS 不被 Arch 挂载、实体 Windows 已经完全关机，且虚拟机没有其他实例正在使用这块分区。</p>
<h3 id="heading-20" data-id="heading-20">KVM Windows → 实体 Windows</h3>
<p>在 Windows 客体内正常关机：</p>
<pre><code class="hljs language-powershell"><code class="hljs language-powershell" data-raw="shutdown%20%2Fs%20%2Ft%200"><div class="code-row">
            <span class="line-num" data-num="1"></span>
            <span class="code-content">shutdown /s /t <span class="hljs-number">0</span></span>
          </div></code>
</code></pre><p>回到 Arch：</p>
<pre><code class="hljs language-bash"><code class="hljs language-bash" data-raw="sudo%20virsh%20-c%20qemu%3A%2F%2F%2Fsystem%20domstate%20win11%20%20%23%20%E5%BA%94%E4%B8%BA%20shut%20off%0Asudo%20winvm%20stop%0Asudo%20reboot"><div class="code-row">
            <span class="line-num" data-num="1"></span>
            <span class="code-content"><span class="hljs-built_in">sudo</span> virsh -c qemu:///system domstate win11  <span class="hljs-comment"># 应为 shut off</span></span>
          </div><div class="code-row">
            <span class="line-num" data-num="2"></span>
            <span class="code-content"><span class="hljs-built_in">sudo</span> winvm stop</span>
          </div><div class="code-row">
            <span class="line-num" data-num="3"></span>
            <span class="code-content"><span class="hljs-built_in">sudo</span> reboot</span>
          </div></code>
</code></pre><p>在 BIOS/UEFI 启动菜单选择物理 SSD 原有的 <strong>Windows Boot Manager</strong>。<code>winvm stop</code> 只清理临时映射，不删除虚拟 EFI 文件；<strong>不要删除 <code>efi-head.img</code>、<code>gpt-tail.img</code></strong>。</p>
<h3 id="heading-21" data-id="heading-21">只读查看实体 Windows 文件（维护场景）</h3>
<p>在 VM <strong>完全关闭</strong>、<code>winvm stop</code> 成功、MD 不再存在后：</p>
<pre><code class="hljs language-bash"><code class="hljs language-bash" data-raw="sudo%20mkdir%20-p%20%2Fmnt%2Fwindows%0Asudo%20mount%20-t%20ntfs3%20-o%20ro%20%2Fdev%2Fnvme0n1p3%20%2Fmnt%2Fwindows%0A%23%20%E6%9F%A5%E7%9C%8B%E5%AE%8C%E6%88%90%E5%90%8E%0Asudo%20umount%20%2Fmnt%2Fwindows%0Asudo%20winvm%20start"><div class="code-row">
            <span class="line-num" data-num="1"></span>
            <span class="code-content"><span class="hljs-built_in">sudo</span> <span class="hljs-built_in">mkdir</span> -p /mnt/windows</span>
          </div><div class="code-row">
            <span class="line-num" data-num="2"></span>
            <span class="code-content"><span class="hljs-built_in">sudo</span> mount -t ntfs3 -o ro /dev/nvme0n1p3 /mnt/windows</span>
          </div><div class="code-row">
            <span class="line-num" data-num="3"></span>
            <span class="code-content"><span class="hljs-comment"># 查看完成后</span></span>
          </div><div class="code-row">
            <span class="line-num" data-num="4"></span>
            <span class="code-content"><span class="hljs-built_in">sudo</span> umount /mnt/windows</span>
          </div><div class="code-row">
            <span class="line-num" data-num="5"></span>
            <span class="code-content"><span class="hljs-built_in">sudo</span> winvm start</span>

</code></pre><p>如果 Windows 仍处于休眠状态或挂载报“不安全”，不要用 <code>force</code> 或 <code>remove_hiberfile</code> 绕过保护。<strong>严禁 Windows 客体运行期间让 Arch 再挂载同一 NTFS</strong>。</p>
